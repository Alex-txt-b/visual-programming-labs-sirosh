## 1. Назначение и архитектура
Redis (Remote Dictionary Server) — быстрая резидентная (in-memory) система управления базами данных класса NoSQL с открытым исходным кодом, работающая со структурами данных типа «ключ — значение». 

В рамках лабораторной работы Redis развернут в едином Docker Compose стеке с n8n и используется для:
- Быстрого кэширования промежуточных состояний автоматизаций;
- Временного хранения уникальных ключей и флагов выполнения;
- Межсервисного взаимодействия без задержек дискового ввода-вывода.

## 2. Конфигурация запуска (Docker)
Контейнер Redis поднят на базе легковесного образа `redis:alpine`:
- Внутренний и проброшенный порт: `6379:6379`
- Сетевой хост внутри Docker: `redis`
- Персистентность данных: примонтирован volume `./redis_data:/data`

## 3. Настройка Credential в n8n
Для взаимодействия с базой в n8n настроен профиль аутентификации:
- **Host:** `redis`
- **Port:** `6379`
- **Password:** отсутствует (локальный защищенный контур)

## 2. Реализация операций в n8n (`flow-07-redis.json`)
В рамках лабораторной работы собран сценарий из 4 последовательных шагов:
1. **Создание ключа (SET):**  
   Нода `1. Redis: Set Key`. Ключ `sirosh:ii241:status` со значением `Active - Lab 4 completed by Sirosh Sasha`. Ответ: `OK` (`screenshots/08-redis-set.png`).
2. **Чтение значения (GET):**  
   Нода `2. Redis: Get Key`. Извлечение сохраненной строки для валидации (`screenshots/09-redis-get.png`).
3. **Удаление (DEL):**  
   Нода `3. Redis: Delete Key`. Удаление ключа из памяти Redis. Возвращается счетчик удаленных записей: `1` (`screenshots/10-redis-del.png`).
4. **Проверка отсутствия:**  
   Нода `4. Redis: Verify Absence`. Повторный запрос `GET` по удаленному ключу возвращает `null` (пустой ответ), подтверждая факт удаления (`screenshots/11-redis-check-empty.png`).

## 3. Проверка через redis-cli
Операции продублированы через консольную утилиту внутри контейнера (`screenshots/12-redis-cli.png`):
```bash
